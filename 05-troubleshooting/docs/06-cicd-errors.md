# 06 — CI/CD & App Service Errors

Errors encountered during the GitHub Actions + Azure App Service deployment pipeline setup in Phase 10.

---

## Error 1 — Publish Profile Invalid

**Symptom**
```
Error: Publish profile is invalid for app-name and slot-name provided.
```

**Cause**
The `app-name` in `deploy.yml` was set to `app-daniellab` but the actual App Service name includes a suffix generated by Bicep: `app-daniellab-2603`.

**Fix**
```powershell
# Get the exact App Service name
az webapp list --resource-group rg-daniellab-v3 --query "[].name" --output tsv

# Update deploy.yml with the correct name
(Get-Content ".github\workflows\deploy.yml") `
  -replace "app-name: app-daniellab", "app-name: app-daniellab-2603" `
  | Set-Content ".github\workflows\deploy.yml"

git add .
git commit -m "fix: correct app service name in workflow"
git push
```

**Lesson**
Always verify the exact resource name after Bicep deployment — suffixes make names non-obvious.

## Error 2 — BAK Incompatible (SQL Version Mismatch)

**Symptom**
```
Msg 3169: The database was backed up on a server running database version 998.
That version is incompatible with this server, which supports version 957.
```

**Cause**
The `.bak` file was created on SQL Server 2025 (v998) but the VM had SQL Server 2022 (v957) installed. SQL Server backups cannot be restored on older versions.

**Diagnosis**
```powershell
# Check installed version on VM
sqlcmd -S ".\SQLEXPRESS" -C -Q "SELECT @@VERSION"

# Check BAK version
sqlcmd -S ".\SQLEXPRESS" -C -Q "RESTORE HEADERONLY FROM DISK = 'C:\SQLBackups\DanielDB.bak'"
# Look at SoftwareVersionMajor field: 15=2019, 16=2022, 17=2025
```

**Fix**
Uninstall SQL Server 2022 and install SQL Server 2025 Express on the VM:

```powershell
# Uninstall SQL 2022
C:\SQLMedia\SQLEXPR_x64_ENU.exe /ACTION=Uninstall /FEATURES=SQLEngine /INSTANCENAME=MSSQLSERVER /QUIET

# Download and install SQL 2025
Invoke-WebRequest `
  -Uri "https://download.microsoft.com/download/7ab8f535-7eb8-4b16-82eb-eca0fa2d38f3/SQL2025-SSEI-Expr.exe" `
  -OutFile "C:\sql2025.exe"

C:\sql2025.exe /ACTION=Download /MEDIAPATH=C:\SQLMedia2025 /MEDIATYPE=Core /QUIET

C:\SQLMedia2025\SQLEXPR_x64_ENU.exe /ACTION=Install `
  /FEATURES=SQLEngine `
  /INSTANCENAME=MSSQLSERVER `
  /SQLSYSADMINACCOUNTS="BUILTIN\Administrators" `
  /TCPENABLED=1 `
  /NPENABLED=1 `
  /IACCEPTSQLSERVERLICENSETERMS `
  /QUIET
```

**Lesson**
Always verify the SQL Server version used to create the backup before provisioning the VM. Version must be equal or higher on the restore target.

## Error 3 — Container Timeout on Startup

**Symptom**
```
Container did not start within expected time limit of 230s.
Site container terminated during site startup.
```

**Cause**
The SQL connection was established at application startup (before the app was ready to serve requests). If SQL Server took more than a few seconds to respond, the container exceeded the 230s startup timeout and was killed.

```csharp
// WRONG — blocks startup
var secret = await kvClient.GetSecretAsync("ConnectionString-DanielDB");
string connString = secret.Value.Value;
var conn = new SqlConnection(connString);
await conn.OpenAsync(); // if this hangs, container times out
```

**Fix**
Move the SQL connection inside the endpoint handler (lazy initialization):

```csharp
// CORRECT — only connects when a request arrives
app.MapGet("/", async () =>
{
    string connString = Environment.GetEnvironmentVariable("SQLCONNSTR_DanielDB")
                     ?? builder.Configuration.GetConnectionString("DanielDB")
                     ?? throw new Exception("Connection string not found");

    using var conn = new SqlConnection(connString);
    await conn.OpenAsync();
    // ...
});
```

**Lesson**
Never open external connections (SQL, Key Vault, APIs) during application startup in App Service Linux containers. Always use lazy initialization inside endpoint handlers.

## Error 4 — SqlClient v6 Crash on Linux

**Symptom**
```
Aborted (core dumped)
dotnet "DanielPortfolio.dll"
at Program.<Main>$(String[] args) in Program.cs:line 3
```

**Cause**
`Microsoft.Data.SqlClient` version 6.x has compatibility issues with some Linux configurations on Azure App Service, causing a native crash at startup.

**Fix**
Downgrade to version 5.2.2 in the `.csproj`:

```xml
<PackageReference Include="Microsoft.Data.SqlClient" Version="5.2.2" />
```

```powershell
git add .
git commit -m "fix: downgrade SqlClient to 5.2.2 for Linux compatibility"
git push
```

**Lesson**
When targeting Linux App Service plans, prefer stable/LTS versions of native-dependent packages. Version 5.2.2 is stable and fully compatible with .NET 8 on Linux.

## Error 5 — Login Failed for User sqladmin

**Symptom**
```
Error de conexión: Login failed for user 'sqladmin'.
```

**Cause**
The user `sqladmin` existed only as a Windows login (`vm-sql01\sqladmin`), not as a SQL Server login with password. The App Service connects over the network using SQL authentication, not Windows authentication.

**Diagnosis**
```powershell
sqlcmd -S ".\SQLEXPRESS" -C -Q "
SELECT name, type_desc FROM sys.server_principals
WHERE type IN ('S','U') ORDER BY name"
# sqladmin appeared as WINDOWS_LOGIN, not SQL_LOGIN
```

**Fix**
```powershell
# Create SQL login
sqlcmd -S ".\SQLEXPRESS" -C -Q "
CREATE LOGIN sqladmin WITH PASSWORD = 'YourPassword';
ALTER SERVER ROLE sysadmin ADD MEMBER sqladmin;
"

# Create user in DanielDB
sqlcmd -S ".\SQLEXPRESS" -C -d DanielDB -Q "
CREATE USER sqladmin FOR LOGIN sqladmin;
ALTER ROLE db_owner ADD MEMBER sqladmin;
"
```

**Lesson**
SQL Server Express installs with Windows Authentication by default. When external services need to connect, Mixed Mode must be enabled during installation and SQL logins created explicitly.

## Error 6 — SQLEXPRESS Dynamic Port

**Symptom**
```
netstat -an | findstr "1433"
# No output — port 1433 not listening
```

**Cause**
SQL Server Express uses dynamic ports by default instead of the standard 1433. The connection string had `,1433` but the instance was listening on a random port assigned at startup.

**Fix**
Fix the port to 1433 via registry and restart the service:

```powershell
Set-ItemProperty `
  -Path "HKLM:\SOFTWARE\Microsoft\Microsoft SQL Server\MSSQL17.SQLEXPRESS\MSSQLServer\SuperSocketNetLib\Tcp\IPAll" `
  -Name "TcpPort" -Value "1433"

Set-ItemProperty `
  -Path "HKLM:\SOFTWARE\Microsoft\Microsoft SQL Server\MSSQL17.SQLEXPRESS\MSSQLServer\SuperSocketNetLib\Tcp\IPAll" `
  -Name "TcpDynamicPorts" -Value ""

Restart-Service -Name "MSSQL`$SQLEXPRESS" -Force

# Verify
netstat -an | findstr "1433"
# TCP 0.0.0.0:1433  LISTENING ✅
```

**Lesson**
Always fix SQL Server Express to a static port when used with VNet Integration. Dynamic ports are unpredictable and connection strings cannot account for them.

## Error 7 — VNet Integration Lost After Redeploy

**Symptom**
```powershell
az webapp vnet-integration list --name app-daniellab-2603 --resource-group rg-daniellab-v3
# []  ← empty, integration gone
```

**Cause**
VNet Integration was configured on a previous App Service instance. After redeploying the infrastructure via Bicep, the new App Service instance did not retain the VNet Integration configuration.

**Fix**
```powershell
# Create dedicated subnet for App Service (cannot share with VM)
az network vnet subnet create `
  --resource-group rg-daniellab-v3 `
  --vnet-name vnet-daniellab-2603 `
  --name snet-appservice `
  --address-prefix 10.0.3.0/24

# Re-add VNet Integration
az webapp vnet-integration add `
  --name app-daniellab-2603 `
  --resource-group rg-daniellab-v3 `
  --vnet vnet-daniellab-2603 `
  --subnet snet-appservice

# Verify
az webapp vnet-integration list `
  --name app-daniellab-2603 `
  --resource-group rg-daniellab-v3 `
  --query "[].{Subnet:subnetResourceId}" --output table
```

**Lesson**
VNet Integration is not persisted in the Bicep template used for this lab. For production, add the `vnetRouteAllEnabled` and subnet delegation to the Bicep `Microsoft.Web/sites` resource to make it reproducible.
